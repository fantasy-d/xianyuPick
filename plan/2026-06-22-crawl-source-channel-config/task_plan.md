# 任务计划：商品爬取与筛选配置增加货源渠道配置

> 计划状态：已完成

## 目标
在“系统参数配置 -> 商品爬取与筛选配置”中新增“货源渠道配置”能力，使抓取链路可以显式选择要参与商品爬取的货源渠道与账号范围，并与现有“货源渠道号池”联动；同时保证职责边界清晰，不与既有“货源渠道号池”账号管理能力重叠，不与已完成计划冲突。除此之外，抓取产出的“决策资产库”也需要能回显资产使用了哪些渠道，并在详情页按渠道分组展示货源结果。

已完成

## 目标交付物
- “商品爬取与筛选配置”卡片新增“货源渠道配置”区块
- `crawl_config` 或等效配置结构支持保存货源渠道相关参数
- 抓取入口可读取“启用哪些货源渠道 / 使用哪些激活账号”
- 前端页面能基于“货源渠道号池”的登录成功账号进行可视化选择
- “决策资产库”列表卡片可展示每个资产使用了哪些货源渠道
  说明：
  - 至少能一眼看出当前资产用了哪些渠道
  - 多渠道资产不能再只显示一组混合货源结果
- “决策资产 / 货源明细”详情页按渠道分组展示货源，而不是混在一个平铺列表中
  说明：
  - 详情接口与前端都必须有清晰的渠道分组概念
  - 同一资产下不同渠道的货源结果要天然分区展示
- 资产侧数据结构可追踪每条货源来自哪个 `channel_id / channel_label / account_id`
- 保存、读取、默认值、空配置、禁用状态、无可用账号提示都有明确规则
- 测试与联调方案覆盖 UI、配置归一化与抓取入口透传

## 设计原则
- “货源渠道号池”负责账号池维护、登录维护、状态维护。
- “商品爬取与筛选配置”负责定义“抓取时要用哪些渠道 / 哪些已激活账号 / 是否限定渠道范围”。
- “决策资产库”负责回显“本次资产实际用了哪些渠道”，因此抓取落库时必须保留渠道元数据，而不是只保留 `ali1688_sources` 的价格与标题。
- 不允许在抓取配置里直接维护浏览器目录、状态文件路径、Cookie 来源等运行时字段。
- 仅允许选择“登录成功且已加入当前激活账号”的账号进入抓取范围。
- 首期可以先以 `ali1688` 为主，但配置结构必须能兼容多渠道。
- 新增配置必须走新结构，不再额外保留旧结构兼容分支。

## 目标配置草案

```json
{
  "crawl_config": {
    "source_limit_1688": 10,
    "source_filter_models": [],
    "source_channel_selection_mode": "active_pool",
    "enabled_source_channels": [
      {
        "channel_id": "ali1688",
        "enabled": true,
        "account_ids": [
          "ali1688-account-1",
          "ali1688-account-2"
        ]
      }
    ]
  }
}
```

## 待确认设计决策
- `source_channel_selection_mode` 是否需要首期落地
  - 方案 A：仅保存 `enabled_source_channels`
  - 方案 B：增加模式位，如 `all_active / custom_selected`
  - 当前建议：保留模式位，便于后续扩展
- “账号范围”是否允许按渠道级别仅勾选部分账号
  - 当前建议：允许
- 若渠道已启用但账号全部失效，保存时是否自动剔除
  - 当前建议：保存时保留渠道结构，但运行时跳过无可用账号

## 风险与关注点
- 若当前抓取入口仍强依赖单一 1688 账号，直接升级到“多账号参与”可能波及较大。
- 若“货源渠道号池”的激活账号集合与抓取配置都可多选，需要避免双重选择逻辑冲突。
- 若账号登录态变化频繁，抓取配置 UI 需要避免抖动或隐式清空用户选择。
- 前端不应让用户误以为“在这里勾选账号 = 完成登录”；这里仅是“参与抓取”的配置。
- 若资产入库时不保存渠道元数据，后续“决策资产库展示渠道”只能靠运行时猜测，历史数据会不可靠。
- 若详情页仍沿用纯扁平 `sources` 结构，多渠道展示会越来越混乱，最好尽早确定分组策略。

## 当前建议结论
- 抓取配置新增“货源渠道配置”，但只消费“货源渠道号池”的已登录成功激活账号。
- 新增字段建议放在 `crawl_config` 下，不放进 `source_channels`。
- 首期运行时建议优先做“按渠道选择 + 每渠道使用被选中的账号集合”，是否真正多账号轮询可在实现阶段再收敛。
- 本计划必须同时覆盖“决策资产库渠道回显”：
  - 资产列表展示“使用了哪些渠道”
  - 资产详情页按渠道分组展示货源
  - 抓取落库阶段保留渠道元数据，避免历史资产无法回显
