## 成功标准
- 能明确回答“是否可以替代”，并按能力项给出证据。
- 只读能力至少覆盖商品列表、状态、运费模板、发布预请求。
- 如果进入副作用验证，必须获得用户针对发布/下架/删除的明确确认。
- 不破坏当前系统已有闲管家 OpenAPI 代码路径。

## 关键问题
1. 官方工作台 mtop 接口能否在后端稳定复刻签名和登录态，还是必须依赖浏览器上下文。
2. 发布页的“宝贝描述 + 图片智能识别”模型能否稳定映射当前系统的 `title/images/sku_items`。
3. 图片上传是否能接收远程 URL，还是必须走文件/媒体上传链路。
4. 下架、删除、编辑、状态同步的返回是否足够稳定可审计。

## 已做决策
| 决策 | 理由 |
|------|------|
| POC 先只读，真实发布/下架/删除需二次确认 | 避免对用户真实闲鱼账号产生不可逆或误导性副作用 |
| 新建独立计划目录 | 避免和已有渠道/1688 计划冲突 |
| 不直接改 `PublisherV3` | 当前 OpenAPI 是稳定主链路，工作台接口尚未证明可生产替代 |
| 只读静态探针先作为 POC 工件 | 可重复运行，不依赖用户登录态，不触发真实业务动作 |
| 阶段 5 必须等待用户确认 | 真实发布/下架/删除会影响用户闲鱼账号，不能由 POC 自动推进 |

## 遇到的错误
| 错误 | 尝试次数 | 解决方案 |
|------|---------|---------|
| 直接重放已签名 `h5api` URL 返回非法请求 | 1 | 改为页面渲染证据 + 浏览器会话只读探针 |
| 浏览器只读沙箱无法直接枚举/读取部分运行态 | 2 | 改为脚本级 Playwright 会话探针 |
| 读取 response body 偶发回收或卡住 | 2 | 增加响应任务等待和单响应超时 |
